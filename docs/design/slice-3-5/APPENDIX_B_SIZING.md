# Appendix B — Sizing: row counts, storage, load times

Part of [DESIGN.md](DESIGN.md) §2.8–§2.10.

## B.1 Model

The estimate simulates the fleet model of DESIGN §2.2–§2.3 at the account
level (Python 3.11, seed 42) and counts FOCUS rows per day at the
recommended grain (D-01). It is an **estimate for sizing**, not the
generator; the generator (PR 3-1) measures the real numbers, and PR 3-4
records them.

| Parameter | Value |
|---|---|
| Account monthly spend | log-normal, median $800, σ = 1.8 (log scale) |
| Services per account | `round(3 + 4·log10(1 + spend/100) + N(0, 2))`, clamped to 1…80 |
| Regional services | 70 %; a regional series spends in 1 region, +1 with probability 0.35 each, max 6 |
| Commitment accounts | 60 % of accounts above $20 k/month, 10 % of the rest; their top 3 services carry an extra Committed row per region |
| Untagged remainder row | 30 % of account-services |
| Dynamic (spot) split | 8 % of account-services, one extra row per region |
| Monthly non-usage rows | 1 tax + 1 recurring fee per account; credits on 15 % of accounts; 3 purchase-related rows per commitment account |
| Stored bytes per fact row | 0.6 KB (target for lean extra columns) to 1.03 KB (measured on the public FOCUS 1.0 sample, Slice 2b EVIDENCE §6, of which 0.67 KB `extra_columns`) |
| Load rates | 20 k rows/s (Slice 1: 200 k narrow synthetic rows in ≈ 10 s, per-row trigger included) and 6 k rows/s (Slice 2b: 10 k real-shaped rows in 1.6 s end to end); **neither measured at tens of millions of rows** |
| Rollup bytes per row (incl. primary-key index) | 160–190 B for `cost_daily` **(assumption)** |
| Resources per series (charge-level comparison only) | 25 **(assumption)** |

The `ci` profile in DESIGN §2.8 uses 4 periods (0.24 M rows); `dev` and
`fleet-15k` use 13 (D-02).

**Generated bytes (assumption):** ≈ 350–450 B of CSV text per row, ≈ 70 B
gzipped (the rows of one series are highly repetitive), so ≈ 30 GB of text
streamed and **≈ 5–6 GB of gzip objects** for `fleet-15k`; evidence capture
stores the same bytes again (≈ 11 GB in local S3 in total).

**Disk for a `fleet-15k` run (assumption):** facts 47–81 GB + rollups and
forecast tables ≈ 12 GB + WAL and checkpoint headroom ≈ 10 GB + local S3
≈ 11 GB + generator output ≈ 6 GB ⇒ **≥ 150 GB free** recommended.

## B.3 Consequences

1. **Charge-level or resource-level generation is not feasible locally**
   (1.45–34.8 B rows); the aggregated daily grain is (D-01).
2. **`fleet-15k` is an on-demand run** (D-03): CI cannot hold 47–81 GB.
3. **D-09 must be reviewed** (DESIGN F4): ≈ 6 M rows per month crosses its
   "a few million rows" trigger. At 10–18 µs per row, the per-row trigger
   costs ≈ 13–24 min over 78.6 M rows.
4. **Parallel sources:** 36 sources (one per billing account) can sync in
   parallel; the lease is per source. 4 in parallel is the planned setting;
   the measured speed-up is a PR 3-4 output.
5. **Batch sizes stay inside the worker's limits:** the largest billing
   account holds ≈ 15 % of rows, ≈ 0.9 M rows per monthly batch (limit
   20 M); files are split at ≤ 500 k rows.
6. **Rollups are ≈ 5× narrower than facts** and are what the analytics job
   and the API scan repeatedly; facts are read once per published batch.

## B.4 Reproducing the estimate

Python 3 standard library only. SHA-256 of the script as run:
`aa166e858c90cd2676e3bbaafe7ee3a93b1f656d917cc226ed88695d10469ca3`.
Save it as `sizing.py` and run `python3 sizing.py 150`, `1500` and `15000`.
It is a design aid, not part of the product, and is not committed as code.

```python
import random, math, statistics, sys
random.seed(42)
N = int(sys.argv[1]) if len(sys.argv) > 1 else 15000
# account monthly spend, lognormal heavy tail
spend = [math.exp(random.gauss(math.log(800), 1.8)) for _ in range(N)]
tot = sum(spend); s = sorted(spend, reverse=True)
print("accounts", N)
print("fleet monthly spend $%.1fM" % (tot / 1e6), "median %.0f p90 %.0f p99 %.0f max %.0f" % (statistics.median(spend), s[int(.1 * N)], s[int(.01 * N)], s[0]))
print("top1%% share %.1f%%  top10%% share %.1f%%" % (100 * sum(s[:N // 100]) / tot, 100 * sum(s[:N // 10]) / tot))
rows_day = 0; series = 0; usage_series = 0
svc_counts = []
commit_accts = 0
for m in spend:
    k = max(1, min(80, round(3 + 4 * math.log10(1 + m / 100) + random.gauss(0, 2.0))))
    svc_counts.append(k)
    series += k
    commit = (m > 20000 and random.random() < 0.6) or random.random() < 0.1
    commit_accts += commit
    for j in range(k):
        regional = random.random() < 0.7
        r = 1
        if regional:
            while r < 6 and random.random() < 0.35:
                r += 1
        rows = r
        if commit and j < 3:
            rows += r      # committed + standard split for top services
        if random.random() < 0.3:
            rows += 1      # untagged remainder row
        if random.random() < 0.08:
            rows += r      # dynamic/spot split
        rows_day += rows; usage_series += r
print("services/account mean %.1f median %d p99 %d max %d" % (statistics.mean(svc_counts), statistics.median(svc_counts), sorted(svc_counts)[int(.99 * N)], max(svc_counts)))
print("commit accounts", commit_accts)
print("account x service series", series, " account x service x region series", usage_series)
monthly_other = N * 1 + int(.15 * N) + commit_accts * 3 + N
rows_day_total = rows_day + monthly_other / 30.4
print("usage rows/day %d ; other rows/month %d ; total rows/day %.0f" % (rows_day, monthly_other, rows_day_total))
for days, label in [(120, '120 days'), (212, '7 periods'), (395, '13 periods')]:
    r = rows_day_total * days
    print(label, "rows %.2fM" % (r / 1e6), "storage @0.6KB %.1f GB  @1.03KB %.1f GB" % (r * 0.6 / 1e6, r * 1.033 / 1e6),
          "load @20k/s %.0f min  @6k/s %.0f min" % (r / 20000 / 60, r / 6000 / 60))
print("month rows (30.4d) %.2fM" % (rows_day_total * 30.4 / 1e6))
# rollups: bytes per row include the primary-key index (assumption)
for days in (395,):
    rr = series * days
    print("rollup acct x svc x day rows %.1fM, @130B %.1f GB" % (rr / 1e6, rr * 130 / 1e9))
    rr2 = usage_series * days
    print("cost_daily (acct x svc x region x day) rows %.1fM, @160-190B %.1f-%.1f GB" % (rr2 / 1e6, rr2 * 160 / 1e9, rr2 * 190 / 1e9))
# charge level, for comparison (assumption: 25 resources per series)
res_per_series = 25
print("charge-level resource x hourly over 395d: %.1fB rows" % (usage_series * res_per_series * 24 * 395 / 1e9))
print("resource x daily over 395d: %.2fB rows" % (usage_series * res_per_series * 395 / 1e9))
```
