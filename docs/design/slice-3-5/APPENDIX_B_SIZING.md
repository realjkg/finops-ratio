# Appendix B — Sizing: row counts, storage, load times

Part of [DESIGN.md](DESIGN.md) §2.8–§2.10. B.1–B.4 size the **full grain** (`ci`, `full`); **B.5 budgets `fleet15k`** from per-row sizes measured on PostgreSQL 16 (revision 3).

## B.1 Model

The estimate simulates the fleet model of DESIGN §2.2–§2.3 at the account
level (Python 3.11, seed 42) and counts FOCUS rows per day at the
full grain of D-01 (`ci` and `full`). It is an **estimate for sizing**, not the
generator; the generator (PR 3-1) measures the real numbers, and PR 3-4
records them.

| Parameter | Value |
|---|---|
| Account monthly spend | log-normal, median $800, σ = 1.8 (log scale) |
| Services per account | `round(3 + 4·log10(1 + spend/100) + N(0, 2))`, clamped to 1…80 |
| Regional services | 70 %; a regional series spends in 1 region, +1 with probability 0.35 each, max 6 |
| Commitment accounts | 60 % of accounts above $20 k/month, 10 % of the rest; their top 3 services carry an extra Committed row per region |
| Untagged remainder row | 30 % of account-services |
| Dynamic (spot) split | 8 % of account-services, one extra row per region |
| Monthly non-usage rows | 1 tax + 1 recurring fee per account; credits on 15 % of accounts; 3 purchase-related rows per commitment account |
| Stored bytes per fact row | 0.6 KB (target for lean extra columns) to 1.03 KB (measured on the public FOCUS 1.0 sample, Slice 2b EVIDENCE §6, of which 0.67 KB `extra_columns`) |
| Load rates | 20 k rows/s (Slice 1: 200 k narrow synthetic rows in ≈ 10 s, per-row trigger included) and 6 k rows/s (Slice 2b: 10 k real-shaped rows in 1.6 s end to end); **neither measured at tens of millions of rows** |
| Rollup bytes per row (incl. primary-key index) | 160–190 B for `cost_daily` **(assumption)** |
| Resources per series (charge-level comparison only) | 25 **(assumption)** |

`fleet15k` uses a different grain and is sized in B.5.

**Generated bytes (assumption):** ≈ 350–450 B of CSV text per row, ≈ 70 B
gzipped (the rows of one series are highly repetitive), so ≈ 30 GB of text
streamed and **≈ 5–6 GB of gzip objects** for `full`; evidence capture
stores the same bytes again (≈ 11 GB in local S3 in total).

**Disk for a `full` run (assumption):** facts 47–81 GB + rollups and
forecast tables ≈ 12 GB + WAL and checkpoint headroom ≈ 10 GB + local S3
≈ 11 GB + generator output ≈ 6 GB ⇒ **≥ 150 GB free** recommended.

## B.3 Consequences

1. **Charge-level or resource-level generation is not feasible locally**
   (1.45–34.8 B rows); the aggregated daily grain is (D-01).
2. **`full` is an on-demand run on the owner's environment** (D-03, OA-1):
   neither CI nor this container class (≈ 10 GB free) can hold 47–81 GB.
3. **D-09 must be reviewed** (DESIGN F4): ≈ 6 M rows per month crosses its
   "a few million rows" trigger. At 10–18 µs per row, the per-row trigger
   costs ≈ 13–24 min over 78.6 M rows.
4. **Parallel sources:** 36 sources (one per billing account) can sync in
   parallel; the lease is per source. 4 in parallel is the planned setting;
   the measured speed-up is a PR 3-4 output.
5. **Batch sizes stay inside the worker's limits:** the largest billing
   account holds ≈ 15 % of rows, ≈ 0.9 M rows per monthly batch (limit
   20 M); files are split at ≤ 500 k rows.
6. **Rollups are ≈ 5× narrower than facts** and are what the analytics job
   and the API scan repeatedly; facts are read once per published batch.

random.seed(42)
N = int(sys.argv[1]) if len(sys.argv) > 1 else 15000
# account monthly spend, lognormal heavy tail
spend = [math.exp(random.gauss(math.log(800), 1.8)) for _ in range(N)]

print("accounts", N)
print("fleet monthly spend $%.1fM" % (tot / 1e6), "median %.0f p90 %.0f p99 %.0f max %.0f" % (statistics.median(spend), s[int(.1 * N)], s[int(.01 * N)], s[0]))
print("top1%% share %.1f%%  top10%% share %.1f%%" % (100 * sum(s[:N // 100]) / tot, 100 * sum(s[:N // 10]) / tot))
rows_day = 0; series = 0; usage_series = 0
svc_counts = []
commit_accts = 0
for m in spend:
    k = max(1, min(80, round(3 + 4 * math.log10(1 + m / 100) + random.gauss(0, 2.0))))
    svc_counts.append(k)
    series += k
    commit = (m > 20000 and random.random() < 0.6) or random.random() < 0.1
    commit_accts += commit
    for j in range(k):
        regional = random.random() < 0.7
        r = 1
        if regional:

                r += 1
        rows = r
        if commit and j < 3:
            rows += r      # committed + standard split for top services
        if random.random() < 0.3:
            rows += 1      # untagged remainder row
        if random.random() < 0.08:
            rows += r      # dynamic/spot split
        rows_day += rows; usage_series += r
print("services/account mean %.1f median %d p99 %d max %d" % (statistics.mean(svc_counts), statistics.median(svc_counts), sorted(svc_counts)[int(.99 * N)], max(svc_counts)))
print("commit accounts", commit_accts)
print("account x service series", series, " account x service x region series", usage_series)
monthly_other = N * 1 + int(.15 * N) + commit_accts * 3 + N
rows_day_total = rows_day + monthly_other / 30.4
print("usage rows/day %d ; other rows/month %d ; total rows/day %.0f" % (rows_day, monthly_other, rows_day_total))
for days, label in [(120, '120 days'), (212, '7 periods'), (395, '13 periods')]:
    r = rows_day_total * days
    print(label, "rows %.2fM" % (r / 1e6), "storage @0.6KB %.1f GB  @1.03KB %.1f GB" % (r * 0.6 / 1e6, r * 1.033 / 1e6),
          "load @20k/s %.0f min  @6k/s %.0f min" % (r / 20000 / 60, r / 6000 / 60))
print("month rows (30.4d) %.2fM" % (rows_day_total * 30.4 / 1e6))
# rollups: bytes per row include the primary-key index (assumption)
for days in (395,):
    rr = series * days
    print("rollup acct x svc x day rows %.1fM, @130B %.1f GB" % (rr / 1e6, rr * 130 / 1e9))
    rr2 = usage_series * days
    print("cost_daily (acct x svc x region x day) rows %.1fM, @160-190B %.1f-%.1f GB" % (rr2 / 1e6, rr2 * 160 / 1e9, rr2 * 190 / 1e9))
# charge level, for comparison (assumption: 25 resources per series)
res_per_series = 25
print("charge-level resource x hourly over 395d: %.1fB rows" % (usage_series * res_per_series * 24 * 395 / 1e9))

## B.5 `fleet15k`: disk budget from measured row sizes (revision 3)

### B.5.1 The constraint

`fleet15k` must hold **all 15,000 accounts**, with a **5.5 GB target** and
a **6 GB ceiling** in total per run: object storage, Postgres facts,
rollups, forecasts, indexes, the backtest exports, the control tenant, WAL
and temporary files (orchestrator decisions, 2026-10-04). The container
class it runs in has ≈ 10 GB free disk, 4 CPUs and 15 GB RAM. The seeds
(tuning, natural-1, natural-2 [, natural-3], enriched) run
**sequentially**, each ending with `down -v`; the per-run budget is B.5.3,
and the **peak across the sequence**, with the retained evaluator exports,
is B.5.7.

### B.5.4 What does not fit, and why

With the per-row costs of B.5.2 and the rev. 2 item list (i.e. **before**
the items added in rev. 3, so these are lower bounds), keeping **every**
account × service series (≈ 107 k):

| Span | Fact rows | Total (lower bound) | Verdict |
|---|---|---|---|
| 4 periods (122 d) | 13.24 M | ≥ 11.37 GB | does not fit |
| 3 periods (91 d) | 9.87 M | ≥ 8.48 GB | does not fit |
| 2 periods (61 d) | 6.62 M | ≥ 5.68 GB | does not fit the target, and **fails the backtest**: no calibration or held-out block after the 56 days of warm-up |

So with all 15,000 accounts at daily grain, the full service mix cannot fit
at any span that supports the backtest. What fits is all 15,000 accounts
with the **service axis reduced**: `fleet15k`.

### B.5.5 What `fleet15k` gives up

- **Service granularity:** each account keeps its top 2 services (top 1
  below median spend); the tail is one `Other services` series. Labels are
  injected into the full mix **before** folding, at natural rates, so the
  loss is measured: folded labels are reported (detected through
  `Other services` or a parent scope, or lost), not gated. FT-4/FT-5 gate
  on individual leaves only.
- **Region:** no region dimension, so `new_region` and region root causes
  are assessed on `ci` and `full` only.
- **Pricing and tag splits:** commitment effects, commitment expiry and
  tagging loss are whole-series switches.
- **Span:** no 90-day horizon, cohort-pooled intervals only.
- **Data arrival:** idealised (closed months at once); late data and
  month-to-date restatement only on `ci`.

DESIGN §2.8 lists, target by target, what `fleet15k` can and cannot assess.

`budget.py`:

```python
import random, math
# fleet15k disk budget (Appendix B.5, revision 3). Same account model and seed as sizing.py.
# Service shares within an account: geometric, share_i proportional to 0.5**i (dominant 50-60 %).
N = 15000
def run(keep_small, keep_large, large_frac, verbose=False):
    random.seed(42)
    spend = [math.exp(random.gauss(math.log(800), 1.8)) for _ in range(N)]
    cut = sorted(spend, reverse=True)[int(N * large_frac)] if large_frac > 0 else float('inf')
    leaves = other = commit_accts = 0
    eligible = 0                                   # leaves with mean >= 500 / day (USD-equivalent)
    for m in spend:
        k = max(1, min(80, round(3 + 4 * math.log10(1 + m / 100) + random.gauss(0, 2.0))))
        commit_accts += (m > 20000 and random.random() < 0.6) or random.random() < 0.1
        keep = keep_large if m >= cut else keep_small
        w = [0.5 ** i for i in range(k)]; tot = sum(w)
        daily = m / 30.4
        indiv = min(k, keep)
        for i in range(indiv):
            leaves += 1
            eligible += daily * w[i] / tot >= 500
        if k > keep:
            leaves += 1; other += 1
            eligible += daily * sum(w[keep:]) / tot >= 500
    return leaves, other, eligible, commit_accts

DAYS = 122
FACT_B, ROLLUP_B, ROLLUP_SEQ_B, GZ_B = 554.2, 217.0, 193.0, 30.0
def budget(label, keep_small, keep_large, large_frac, batch_seq, control_accounts):
    leaves, other, eligible, commit_accts = run(keep_small, keep_large, large_frac)
    billing_month = N + int(.15 * N) + commit_accts * 3 + N
    unused_rows = commit_accts * DAYS                       # one Unused commitment row per commitment account per day
    facts = (leaves + billing_month / 30.4) * DAYS + unused_rows
    series_days = leaves * DAYS
    scopes = 550
    rows = {
        'facts (554 B/row, measured)': facts * FACT_B,
        'cost_daily (217 B/row measured; 193 B with an int batch key, estimated)': series_days * (ROLLUP_SEQ_B if batch_seq else ROLLUP_B),
        'billing_daily (sparse)': billing_month * 4 * 150,
        'cost_daily_scope (550 scopes x 122 d x 2 runs)': scopes * DAYS * 2 * 220,
        'objects: source + evidence buckets (30 B/row x 2)': facts * GZ_B * 2,
        'forecast state + detector state (2 runs)': leaves * 600 * 2,
        'forecast points + totals, aggregate scopes (2 runs)': scopes * 90 * 2 * 150,
        'backtest leaf points, exported gzip JSONL (178 per leaf x 30 B)': leaves * 178 * 30,
        'backtest aggregate points in DB': scopes * 178 * 120,
        'anomalies, days, root causes, events': 20e6,
        'cost_series, account_dim (2 runs)': leaves * 150 + N * 200 * 2,
        'control tenant (%d accounts, full grain)' % control_accounts: control_accounts * 1600,  # per-account ~1.6 KB/day-equivalent incl. rollup+objects over 122 d
        'WAL (max_wal_size 256 MB, budget)': 0.30e9,
        'temporary files (budget)': 0.30e9,
        'cluster base (catalogs, empty DBs)': 0.05e9,
    }
    # control tenant: ~13.4 fact rows/account/day at full grain (B.2), ~650 B incl. rollup + objects
    rows['control tenant (%d accounts, full grain)' % control_accounts] = control_accounts * 13.4 * DAYS * 900
    total = sum(rows.values())
    print('== %s: leaves %d (Other %d, individual %d), eligible >= $500/day %d, fact rows %.2fM, total %.2f GB'
          % (label, leaves, other, leaves - other, eligible, facts / 1e6, total / 1e9))
    for k, v in rows.items():
        print('   %-75s %6.3f GB' % (k, v / 1e9))
    return total

budget('A: top 2 (top 4 for largest 5 %), uuid batch key, 150-account control', 2, 4, 0.05, False, 150)
budget('B: top 2 for all, uuid batch key, 15-account control', 2, 2, 0.0, False, 15)
budget('C: top 2 for all, int batch key, 15-account control', 2, 2, 0.0, True, 15)
budget('D: top 1 below median, top 2 above, int batch key, 15-account control', 1, 2, 0.5, True, 15)
```

# fleet15k, revision 5: false-positive budget with the calendar component, D1/D2/D3 thresholds,
# pass probabilities, alert-fatigue bounds and peak disk. Standard library only.
# Account model, seed and leaf list are those of budget.py / budget2.py (variant D, 37,052 leaves).

random.seed(42)
spend = [math.exp(random.gauss(math.log(800), 1.8)) for _ in range(N)]
med = sorted(spend, reverse=True)[int(N * 0.5)]
leaves = []                                   # (mean M per day, log-noise s, account index)
for a, m in enumerate(spend):
    k = max(1, min(80, round(3 + 4 * math.log10(1 + m / 100) + random.gauss(0, 2.0))))
    _ = (m > 20000 and random.random() < 0.6) or random.random() < 0.1
    keep = 2 if m >= med else 1

    s = min(0.15, max(0.03, 0.15 - 0.04 * math.log10(max(m, 1) / 100)))   # noise: 15 % small ... 3 % large accounts

def need_rel(L):                              # relative excess per day needed for `warning`
    return max(0.20, MIN / L)
def Q(z):                                     # upper tail of N(0,1)
    return 0.5 * math.erfc(z / math.sqrt(2))
def arl(h, k=0.5):                            # Siegmund, one-sided
    b = h + 1.166

# --- CUSUM alarm episodes (in-control N(0,1), k = 0.5): distribution of the mean z over the run ---
def episodes(h, steps, seed):
    r = random.Random(seed); S = 0.0; run = []; out = []
    for _ in range(steps):
        z = r.gauss(0, 1)
        S = max(0.0, S + z - 0.5)
        if S == 0.0:
            run = []
        else:
            run.append(z)
            if S > h:
                out.append(sum(run) / len(run)); S = 0.0; run = []

def d3_rate(h, eps):

# --- calendar residual for the cohort series (Monte Carlo of the significance-gated estimator) ---
# Events per month: month_start 3 days, mid_month 2 days, month_end 2 business days.
# meb: month_end factor 1.3; mc: month_start and mid_month factors U(1.2, 1.6).
# Estimator: mean log ratio over n prior cycles (d days each); applied only if t = r / (s / sqrt(n d)) >= 3.
# mode 'gated' = the design; mode 'none' = no calendar component (the revision-4 model), for contrast.
def event_alarm_prob(L, s, d, fl_draw, n_prior, zt, h, r, trials, mode):
    hits = 0
    for _ in range(trials):
        fl = fl_draw(r)
        if mode == 'none' or n_prior == 0:
            fhat = 0.0
        else:
            rbar = fl + r.gauss(0, s / math.sqrt(n_prior * d))
            t = rbar / (s / math.sqrt(n_prior * d))
            fhat = rbar if t >= 3 else 0.0
        resid = (fl - fhat) / s
        S = 0.0; fired = False; zs = []
        for _d in range(d):
            z = resid + r.gauss(0, 1)
            zs.append(z)
            S = max(0.0, S + z - 0.5)
            if z >= zt and math.exp(s * z) - 1 >= need_rel(L):
                fired = True
            if S > h and math.exp(s * (sum(zs) / len(zs))) - 1 >= need_rel(L):
                fired = True
        hits += fired
    return hits / trials

    if c == 'meb':

    if c == 'mc':

def poisson(r, lam):
    if lam > 30:
        return max(0, int(round(r.gauss(lam, math.sqrt(lam)))))
    L = math.exp(-lam); k = 0; p = 1.0
    while True:
        p *= r.random()
        if p <= L:
            return k
        k += 1
def wilson_lo(p, n, z=1.96):
    return (p + z * z / (2 * n) - z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n))) / (1 + z * z / n)
def pass_prob(lam, tp_mean=146, days=122, sims=4000, seed=5):
    r = random.Random(seed); ok1 = ok4 = both = 0
    for _ in range(sims):
        tp = poisson(r, tp_mean)
        daily = [poisson(r, lam) for _ in range(days)]
        fp = sum(daily)
        n = tp + fp
        p = tp / n if n else 0
        a1 = n >= 100 and p >= 0.80 and wilson_lo(p, n) >= 0.70
        p95 = sorted(daily)[int(0.95 * days)]
        a4 = fp / days <= 0.30 and p95 <= 2
        ok1 += a1; ok4 += a4; both += a1 and a4
    return ok1 / sims, ok4 / sims, both / sims
